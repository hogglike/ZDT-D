# ZDT-D 4.3.0-mod38 — API-прокси и диагностика Opera

## Как использовать Webshare

Для инструкции с 4PDA нужен прокси **только для API Opera**. Он помогает
авторизоваться и получить серверы Opera. Пользовательские сайты затем идут
через серверы Opera; весь их трафик не должен расходовать лимит Webshare.

В mod37 каталог подключался как внешний прокси для всего трафика Opera.
Этот вариант сохранён, но теперь явно подписан «Для всего трафика · Авто».

1. Установи APK поверх предыдущей версии и обнови модуль через встроенный
   установщик или PLAIN ZIP в ReSukiSU. Перезагрузи телефон.
2. Открой «Прокси». Сохранённый каталог остаётся; повторно импортировать его не нужно.
3. Для TXT Webshare `адрес:порт:логин:пароль` выбери HTTP перед импортом.
4. Нажми **«Для API Opera · весь список» → «Применить к API»**.
5. Если каталог раньше использовался в SNI как внешний прокси, оставь отмеченным
   возврат этих записей к ByeDPI. Иначе весь трафик по-прежнему пойдёт через Webshare.
6. Перезапусти ZDT-D. Открой «Диагностика Opera · проверить SNI».

URL одного прокси: `http://логин:пароль@адрес:порт`.
Rotating endpoint Webshare можно импортировать как один URL: ротацией в этом
случае управляет Webshare. API-ключ Webshare — не пароль прокси; его нельзя
вставлять вместо логина/пароля. Импорт из TXT не требует API-ключа Webshare.

При запуске Opera список проверяется через настоящую авторизацию и получение
серверов. Недоступный или отклонённый API-прокси пропускается. Список не означает
одновременное использование всех прокси и не увеличивает скорость.
Если весь явно заданный список не работает, приложение показывает ошибку;
незаметного перехода к API напрямую больше нет.

## SNI и проверка соединения

В SNI вводится домен, например `m.vk.com` или `vk.com`. Прокси Webshare с портом
и учётными данными не являются SNI. Для каждой записи SNI сохраняется свой
способ соединения: напрямую, ByeDPI, один внешний прокси или Авто.

Новая диагностика по кнопке проверяет до 20 сохранённых записей последовательно:

- настройки и CA;
- авторизацию и получение серверов Opera через API-прокси;
- туннель до сервера Opera (TCP/TLS/CONNECT);
- HTTP/HTTPS-сайт из поля «Адрес проверки серверов» (до 1 КБ ответа).

Если соединение с выбранным SNI не проходит, выполняется контроль без подмены
SNI на том же сервере Opera. Успешный контроль указывает на различие, связанное
с этим SNI, но не доказывает конкретную причину блокировки.
Если оба запроса не проходят, диагностика не объявляет SNI нерабочим без оснований.

Проверка занимает до 90 секунд на запись. Она использует временные процессы,
не переключает действующий VPN и не меняет правила маршрутизации приложений.
Краткий статус работающей Opera отображается отдельно. Логины, пароли и токены
не включаются в копируемый отчёт.

Ошибка `connect/greeting/auth failed` сама по себе не доказывает неверный пароль
Webshare: её может вызвать недоступный локальный SOCKS. Теперь можно проверить
этап API и состояние локального порта отдельно.

## Проверка аргументов

Перед сохранением проверяются формат SNI, URL API-прокси, числовые поля,
интервал и адрес теста. Аргументы ByeDPI проверяет парсер той версии бинарника,
которая установлена в модуле, без запуска слушателя и создания PID-файла.
Ошибка не перезаписывает ранее сохранённую конфигурацию.

Корректный синтаксис не гарантирует обход блокировки: работа стратегии ByeDPI
зависит от сети. Диагностика проверяет сохранённую стратегию запуска;
аргументы перезапуска также проверяются при сохранении.

## Проверки сборки

Release `build.yml` на `copilot-polish`: тесты перебора HTTP/SOCKS5 с авторизацией,
TLS, таймаутов, отмены запросов, отбора API-прокси по результату API, отсутствия
секретов в отчёте и контрольного сравнения SNI. Go-тесты запускаются с детектором
гонок. Проверяется парсер ByeDPI и Rust-валидация. Собираются ARM64/ARM32 и три
варианта APK с Android unit-тестами.

Личные прокси Webshare и сеть телефона в сборочной среде недоступны; их результат
нужно проверить на телефоне новой кнопкой. Версия **4.3.0-mod38**, код **43038**.
Функции для часов не возвращены.
