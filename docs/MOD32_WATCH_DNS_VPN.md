# ZDT-D 4.2.0 · mod32 — DNS для часов по Bluetooth

Продолжение mod31. Обновить APK и PLAIN ZIP до mod32, перезапустить модуль. DNS-профили, подписки и настройки системной раздачи сохраняются.

## Как включить

1. Открой «DNS-профили → DNS для часов · VPN».
2. Выбери уже включённый и запущенный DNS-профиль, например тот, с которым Gemini работает на телефоне.
3. Отметь те же приложения Samsung, с которыми часы заработали через HAPP. Предлагаются установленные Galaxy Wearable / Galaxy Watch7 Manager; список можно изменить. Отключение фильтра «Только Samsung» позволяет выбрать другие пакеты, если нужно для конкретной прошивки.
4. Нажми «Включить DNS часов», подтверди системный запрос Android. Появится ключ VPN и уведомление с кнопкой выключения.
5. Выключи прямые Wi-Fi/LTE на часах, оставь Bluetooth и проверь Gemini. Закрытие экрана настройки не останавливает VPN.

Режим занимает системный VPN-слот и заменяет HAPP. VPN без root в ZDT-D и DNS часов одновременно не запускаются: HEV поддерживает единственный native-сеанс в процессе. Root-режимы подписки ZDT-D этот слот не занимают; совместимость при пересечении списков приложений проверяется на устройстве.

## Как работает

Android VpnService захватывает IPv4/IPv6-трафик только выбранных телефонных приложений связи с часами. HEV передаёт его в существующий loopback-only mixed-вход DNS-профиля. Sing-box перехватывает UDP/TCP порт 53 независимо от исходного DNS-адреса и отправляет запросы к DoH этого профиля. Остальные соединения идут напрямую. Зарубежного VPN-сервера здесь нет; mapdns/FakeIP не используется.

Служба не изменяет конфигурацию, назначения, netd-правила или процесс профиля. В API статуса добавлены `proxy_port` и `config_current`. Второе поле сравнивает runtime-config с текущими настройками, чтобы VPN не подключался к старой конфигурации. После изменения профиля перезапусти ZDT-D и включи DNS часов заново.

Перед созданием TUN служба отправляет настоящий запрос example.com к 8.8.8.8:53 через SOCKS5 UDP выбранного профиля. Требуется ответ DNS с совпадающим ID, успешным кодом и непустым разделом ответов. Это проверяет перехват DNS в ядре, но не подтверждает работу Gemini на часах.

Пустой список установленных приложений отклоняется: Android трактовал бы его как VPN для всех приложений. Собственный пакет ZDT-D исключается для предотвращения петли. При остановке профиля, изменении конфигурации или потере API три раза подряд режим останавливается с ошибкой. Выбор другого Android VPN освобождает TUN; служба не пытается вернуть себе VPN-слот. Автозапуска после перезагрузки нет.

## Проверка

Unit-тесты проверяют пустой allowlist, исключение своего пакета, удалённый companion, недоступный профиль, владение общим HEV-сеансом и реальные пакеты DNS через локальный SOCKS UDP fixture, включая SERVFAIL. CI выполняет существующие реальные UDP/TCP DNS и VLESS/TLS проверки, Android Release unit-тесты и сборку компонентов. Bluetooth-мост Samsung, смена Wi-Fi/мобильной сети, Gemini на телефоне и точка доступа проверяются на устройстве пользователя.

Работа часов через HAPP с зарубежным сервером не доказывает, что достаточно одного Smart DNS. Если DNS отвечает, но Gemini по-прежнему недоступен, потребуется диагностика соединения часов и/или маршрутизация через сервер подписки. DNS-only режим не меняет внешний IP обычных соединений.
