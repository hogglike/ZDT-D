# ZDT-D 4.2.0 · mod31

Продолжение mod30. Устанавливать вместе APK и PLAIN ZIP mod31, затем перезапустить модуль обычным способом. Настройки подписок, режимов и DNS сохраняются.

## Управление

- Кнопки «Обычный» и «Браузер» в виджете напрямую запускают фоновую службу. Экран настроек открывается по шестерёнке.
- «Белый» на Wi-Fi сохраняет подтверждение. Для подтверждения используется отдельная прозрачная задача Android, поэтому настройки после неё не открываются.
- «Сервер ▾» позволяет выбрать ручной сервер или вернуться к Авто, сохранив список и порядок.
- «VPN выкл.» останавливает режим подписки. Это не общий выключатель ZDT-D.
- Дополнительный виджет «ZDT-D · связь и VPN» объединяет три режима, выбор серверов, обновление и проверку Opera/DNS/интернета.

## Обновление серверов

«Обновить серверы» обновляет все включённые подписки, ждёт завершения (до трёх минут), сохраняет очищенный список выбранных серверов и проверяет задержку всех поддерживаемых серверов. Если обновление подписки не удалось, её прежний кэш сохраняется; итог сообщает число таких подписок. Неподдерживаемые транспорты остаются серыми и не получают фиктивную задержку.

Настройки расписания: «Режимы → Серверы и задержка → Автоматически обновлять и проверять». По умолчанию выключено; интервал 60 минут, допустимо 15–10080 минут. Сохранить кнопкой внизу. Выполняется при запущенном ZDT-D, без открытого приложения. Пропущенный срок после запуска отрабатывается один раз. Неудачная попытка тоже учитывается, поэтому нет бесконечных повторов каждую секунду. Обычное расписание подписок остаётся самостоятельным.

Ручная проверка задержки не сдвигает срок следующего обновления подписок. Полный тест расходует трафик и заряд. На каждой попытке обновления подписки могут измениться её данные; это может вызвать существующее восстановление активного VPN-режима. Сама проверка задержек выполняется отдельным sing-box с единственным локальным mixed-входом, без TPROXY и без изменения MODE, приложений или DNS-маршрутов. Запуск/переключение режима не ждёт массовый тест. Общая остановка ZDT-D отменяет тест.

## Изменения подписки и Авто

Порядок сохранившихся выбранных серверов и ручной выбор остаются прежними. Обновление адреса сервера сохраняет его стабильный ID; старый результат задержки для изменённого адреса не используется. Удалённые записи убираются только при полном доступном кэше подписок. Новые серверы добавляются после выбранных по правилам имени, например LTE. Без такого правила их надо отметить вручную. Галочки подписок в правилах имени ограничивают именно этот поиск. Ручной сервер, удалённый провайдером, не подменяется произвольным новым: выбери другой или верни Авто.

## Opera Proxy и DNS

В Opera добавлена сворачиваемая подсказка для первого запуска и переход к реальной проверке связи. В API proxy можно вводить несколько источников по строкам. Типы источников: прямые адреса прокси, ссылки на текстовые списки или пути к файлам; смешивать типы не следует, поскольку существующий backend отдаёт приоритет файлам и ссылкам. Списки уже проверяются и загружаются заново при запуске. API proxy нужен для получения данных Opera; трафик выбранных приложений обслуживается Opera Proxy. В стартовый журнал больше не записывается исходное поле с адресами/паролями API proxy.

В DNS статус «Запущен» означает работу процесса и применение назначения. Ответ DNS подтверждает отдельный реальный запрос расширенного теста. После обновления настроек старый результат теста очищается. В редакторе объяснены DoH URL и роль bootstrap DNS. Рабочие netd/per-app DNS и настройки системной раздачи не переписывались.

## Что проверить на телефоне

1. Обновить оба компонента; повторить «Браузер»/«Обычный» из виджета при закрытых и ранее открытых настройках. Настройки не должны появляться.
2. Проверить отмену и подтверждение «Белого» на Wi-Fi; отмена не меняет подключение.
3. Добавить общий виджет, запустить режим и проверить связь. Прогресс серверов и VPN показываются отдельно.
4. Нажать обновление; дождаться итогового числа серверов. Во время задержек открыть выбранный браузер и DNS-приложение.
5. Включить расписание с интервалом 15 минут, сохранить, закрыть APK. После проверки убедиться, что время и задержки изменились, без постоянного переподключения.
6. Проверить сохранение ручного выбора/Авто и порядка при изменении подписки. Новые LTE должны добавляться по правилу, удалённые пропадать из списка.

CI проверяет сборку Release, настройки/миграцию, расписание и реальные локальные пакеты DNS/TLS/SOCKS/VLESS Reality, включая одновременную работу двух экземпляров sing-box и отказ недоступного сервера без прямого обхода. Проверку конкретного оператора и Android выполняет пользователь на устройстве.

Дальнейшие полезные улучшения: отдельная карточка состояния получения API Opera с краткой причиной последнего отказа; проверка конкретного выбранного SNI, а не только первого локального SOCKS-порта; кнопка теста отдельного DNS-профиля с выбранным доменом. Эти изменения в mod31 не реализованы.
