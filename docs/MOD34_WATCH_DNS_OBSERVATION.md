# ZDT-D 4.2.0-mod34: запись реальных DNS-запросов часов

Отчёт mod33 с пятью выбранными приложениями содержит 13 отправленных и 4 полученных IP-пакета. Проверка профиля по SOCKS UDP/TCP возвращает ответы; Google/Gemini A-записи указывают на 194.5.65.8. Эти данные не показывают DNS-вопросы самих часов, не дают процента потерь и не подтверждают работу HTTPS/API Gemini. Внутренний ID `xbox` не определяет провайдера: выбранный профиль называется Proximizer.

## Использование

1. Установить APK mod34 поверх mod33. Модуль mod32/mod33 совместим; менять его для этой диагностики не требуется.
2. Остановить «DNS часов», включить «Диагностика реальных DNS-запросов», снова включить «DNS часов» с тем же профилем и пятью приложениями.
3. Нажать «Записать DNS · 30 секунд», сразу открыть Gemini на часах по Bluetooth и дождаться результата.
4. После окончания окна нажать «Проверить DNS и скопировать отчёт».

`observed_dns.events` содержит время, сеанс SOCKS, направление, транспорт, исходный адрес SOCKS, DNS ID, имя, тип, RCODE, A/AAAA-ответы и ошибки пересылки. Запись касается выбранных приложений телефона вместе: по ней нельзя без дополнительных данных приписать запрос конкретному приложению или часам. Синтетические тесты идут непосредственно в SOCKS профиля и не попадают в наблюдение. Пустая запись может означать кэш, свой DNS/DoH приложения или другой путь Bluetooth-прокси.

## Границы изменения

Обычный режим использует прежний прямой путь HEV → SOCKS профиля. Дополнительный наблюдатель появляется только при включённой настройке диагностики: HEV → локальный SOCKS-наблюдатель → существующий SOCKS профиля. Он пересылает оригинальные UDP-датаграммы и TCP-байты, не заменяет адреса, не разрешает имена самостоятельно и не создаёт новый DNS-профиль. Поддерживает TCP CONNECT и стандартный UDP ASSOCIATE, только loopback; максимум 16 одновременных сеансов. Закрывается вместе с VPN.

Запись начинается вручную на 30 секунд, ограничена 160 событиями и хранится в памяти. После окна новые события не сохраняются. Содержимое HTTPS и произвольные пакеты не включаются в отчёт. Нет передачи отчёта на сервер. Настройка диагностики выключена по умолчанию. Root per-app DNS, netd, конфиги sing-box, подписки и системная раздача не меняются. Mod34 не заявляет исправление Gemini на часах: проверка на устройстве ещё нужна.

## Проверки

Release `build.yml` на `copilot-polish`: существующие тесты и сборка APK/ZIP. Новые JVM-тесты проверяют реальные loopback SOCKS UDP/TCP передачи, сохранение IPv6-адреса и не-DNS байтов, фрагментированные ответы TCP, закрытие ассоциаций, ограничение/истечение записи, ошибочную DNS-компрессию, пустой AAAA и TC-флаг.
