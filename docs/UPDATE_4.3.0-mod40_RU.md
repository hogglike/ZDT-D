# ZDT-D 4.3.0-mod40 — Telegram WS и исправленный автоподбор Zapret

Версия без функций для часов. Установи APK поверх текущего, обнови модуль ZIP и перезагрузи телефон. Подпись и идентификаторы прежние.

## Telegram как TG WS Proxy

Нужный инструмент называется **Telegram WS Proxy**, а не «Telegram через подписку». Последний сохранён как отдельный запасной вариант и использует VPN-сервер.

1. Открой вкладку с девятью квадратиками. В «Дополнительных утилитах» установи компонент Telegram WS Proxy. Если он уже установлен, переустанови компонент, чтобы получить новое ядро 2.5.8.
2. Открой Telegram WS Proxy в списке инструментов. Вверху появился блок «Быстрая настройка Telegram».
3. Для начала нажми «Cloudflare сначала · затем прямое». Если работает плохо, сравни с «Прямой WebSocket · без Cloudflare». Кнопки сохраняют порт и секрет, свои адреса DC и внешний прокси. Прямой вариант отключает CF-списки и MTProto-резерв; пользовательские настройки лучше предварительно сохранить.
4. Дождись автосохранения. Нажми «Проверить MTProto и WebSocket». Проверяется отдельный временный локальный порт и настоящий ответ MTProto Telegram; действующий локальный порт не занимается и маршруты не меняются. Лимит проверки — 90 секунд. Есть подробный отчёт без секретов.
5. Включи инструмент переключателем, перезапусти основной ZDT-D и нажми «Открыть в Telegram». Подтверди прокси в Telegram. Не используй одновременно второй локальный TG WS на том же порту 1443.

VPN-подписка, Opera и Webshare этому способу не нужны. Внешние CF-домены берутся из списка upstream, когда включён соответствующий режим. В новом ядре исправлены длительные повторные ожидания недоступного прямого адреса, восстановление списка CF после сбоя при старте и другие ошибки соединений. Cloudflare 429, блокировка адресов и особенности сети остаются возможны. Успешный MTProto-тест не гарантирует работу всех датацентров, медиа и звонков; проверь их в Telegram. Долгая проверка пинга в Telegram сама по себе не доказывает, что сообщения не работают.

Режим прямого WebSocket не означает «VPN» или смену страны. Основной ZDT-D должен работать для запуска установленного TG WS-компонента. Локальный прокси в настройках Telegram нужно выключить, когда останавливаешь инструмент.

## Zapret

- На вкладке с девятью квадратиками появилась заметная кнопка «Центр инструментов · автоподбор Zapret». Затем выбери «Тестер стратегий NFQWS». Автоподбор находится вверху.
- Уточнено, что «Обновить состояние» не выключает службу. Для подбора останови ZDT-D кнопкой питания на главной вкладке и выключи другой VPN.
- Автоматический тест теперь направляет в очередь только HTTPS-запросы приложения-сканера и ответы этих соединений. Раньше были только исходящие пакеты: это мешало autottl и стратегиям с настройкой TCP-окна. Ручной плавающий тестер сохраняет свой прежний охват.
- Добавлена проверка поддержки connbytes с ограниченным запасным вариантом для ядер без этого расширения. Правила ответа снимаются вместе с временной стратегией, в том числе сторожем. Если IPv6-правила создать невозможно, это явная ошибка, а не незаметный тест IPv6 мимо стратегии.
- В новый список адресов по умолчанию добавлен i.ytimg.com; ранее сохранённые адреса не меняются.

Это HTTPS-подбор по нажатию кнопки, а не фоновая автоматическая смена рабочих аргументов. Механизмы WARP, раздачи и полного сетевого сторожа из другого модуля не переносились. Не запускай ZDT-D и VPN Tethering Ultra с включённым обходом одновременно: у обоих собственные сетевые правила.

## Источники идей и ядра

- https://github.com/amurcanov/tg-ws-proxy-android — сравнение Android-управления, CF/direct и поведения повторных подключений. Код GPL-форка в приложение не копировался.
- https://github.com/valnesfjord/tg-ws-proxy-rs/tree/v2.5.8 — обновлённое существующее MIT-ядро TG WS, встроенные проверки MTProto и работа с резервными маршрутами.
- https://github.com/JagKubarev/vpn-tethering-ultra — идея ограниченного сканера, обработки ответов для autottl/wssize и проверки возможностей connbytes. Реализация адаптирована к собственному тестеру ZDT-D.

## Проверка

Сборка Release и тесты выполняются workflow build.yml на ветке copilot-polish. Проверка на сети оператора и устройстве пользователя отдельно; программная сборка не подтверждает доступность Telegram и Zapret у оператора.
